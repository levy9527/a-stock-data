## §1 行情

### §1.1 腾讯字段 44/45 曾标反（2026-07-26 修正）

- **结论**：43=振幅%、44=流通市值、45=总市值、46=PB；用市值筛选前先确认总股本与流通股本是否相等。
- **现象**：表里曾把 44 写成总市值、45 写成流通市值。多数股票两者相等，所以看不出来。
- **影响**：总股本 ≠ 流通股本的票（科创板 / 次新 / 有限售股）会差出数倍，用市值做筛选时取错会把大市值公司误判成小盘股。
- **实测**：中船特气（688146）`f[44]=356.15亿`（流通股本 1.45 亿股）、`f[45]=1300.61亿`（总股本 5.29 亿股），差 3.65 倍。
- **旁证**：东财 push2 的 `f116`=总市值 / `f117`=流通市值，方向与腾讯相反，实测确认无误。
- **另一条**：网上很多教程把索引 43 写成 PB，实测 43 是振幅%，PB 在 46。

### §1.2 腾讯前复权是等差口径（茅台样本）

- **结论**：`adjust='qfq'` 的长区间序列早年可能为负；长区间回测取 `adjust=''` 再用 §1.6 因子换算。
- **实测**：茅台 2020-01-02 原始价 1130.00，腾讯 qfq 给 870.741，差额正是此后累计分红；高分红老股早年会被减成负数（茅台 2015 年约 −117.6）。
- **处理**：函数遇到 ≤0 价格直接抛错，不返回负价。

### §1.2 成交量按股对账的实测依据（#57，2026-10-05）

- **结论**：见 §1.2 正文的四条口径（整手取整 / 241 根 / 深市边界 / 缺行）。
- **整手取整的实测**：2020-03-11 起是四舍五入（与盘后包差 −52～+50 股），更早是舍去零头（差 −99～0 股）。
- **回填**：分钟线回填后才出现 34967.59 这样的小数手；回填后当日各根合计与盘后包逐股一致，确切回填时点没测出来。
- **缺行抽样**：2026-09-30 抽 54 只沪深 B 股，第一笔晚于 09:30 的 43 只都从第一笔那分钟才有行；抽 51 只低成交深市股，25 只共缺 64 分钟，抽查的缺失分钟逐笔里都没有成交。
- **对账方法**：用 §1.3 通达信盘后包与 Baostock 5 分钟逐根比对。

### §1.6 复权因子：为什么必须做除法、为什么不能跨源比数值

- **结论**：`qfq` 因子恒 ≥ 1，乘上去会放大历史价；hfq 基准与 baostock 不同，差恒定倍数。
- **验证陷阱**：2026 那行两种算法结果一样，因为最新日因子恰为 1.0 —— 只用最近日期做验证会漏掉这个 bug。
- **hfq 基准差异**：新浪 `raw × hfq` 与 baostock 后复权价差恒定倍数（实测 1.1582，2015 与 2026 两点一致）。
- **自检口径的来历**（2026-08-19 校准）：茅台 `qfq(d) × hfq(d)` 恒为 `8.882513`；`hfq/qfq` 不恒定（茅台 33 个日期有 32 种取值）。
- **北交所**：`bj920982` 实测返回 404（新浪未提供北交所 qfq/hfq 文件），因此函数抛 `HTTPError` 而不是返回空表。

### §1.7 mootdx 行情命令失效（#52，2026-09-20）

- **结论**：`bars` / `quotes` / `transaction` 返回 0 行，K 线与盘口改走腾讯，逐笔改走 §1.4。
- **实测**：逐台测内置 10 台通达信公开服务器，TCP 全部可连，财务与除权除息正常，F10 只剩「最新提示」一类；K 线 / 五档 / 逐笔一律 0 行。换 mootdx 版本解决不了，是服务器端变化。
- **代价**：`tdx_client()` 在 K 线模式下先测速，全部失败约 1 分钟才报错。
- **留档**：代码保留，服务器恢复后可照常使用。

## §2 研报

### §2.1 研报接口只认纯 6 位代码

- **结论**：传 `SH600519` / `600519.SH` 会静默返回 0 篇，先过 `norm_ticker()`。
- **现象**：`reportapi` 只认 `600519` 这种写法；带前缀/后缀时 HTTP 200 但 `hits=0`，和「该股没有研报」长得一模一样。
- **处理**：`eastmoney_reports()` / `ths_eps_forecast()` 内部接 `norm_ticker()`，解析失败抛 `ValueError`。

### §2.2 一致预期返回空表

- **结论**：空表＝该股无机构覆盖（小盘 / 次新 / ST 常见），不是接口坏了；兜底取东财 `predictThisYearEps`。
- **口径**：「预测机构数」< 3 的预期要谨慎使用。

## §3 信号

### §3.3 板块归属从百度 PAE 换到东财 slist（V3.2.2）

- **背景**：百度 PAE `getrelatedblock` 已失效（实测 `ResultCode 10003` + 空数组）。
- **现状**：走东财 `slist`（`spt=3`），一次请求拿全所有板块，零鉴权。
- **注意**：东财把行业 / 概念 / 地域混在**一个列表**返回，板块名本身自解释（「食品饮料」是行业、「贵州板块」是地域、「酿酒概念」是概念），题材归因直接用名字即可。

### §3.4 个股资金流从百度换到东财 push2（V3.1）

- **背景**：百度 PAE `fundflow` / `fundsortlist` 已于 2026-05 下线（返回 null）。
- **现状**：走东财 push2 资金流 API；日级资金流见 §4.5。

### §3.2 北向数据为什么是本地缓存

- **背景**：eastmoney 全系北向数据自 2024-08 起收紧，净买额字段返回 NaN/0，属上游断供。
- **现状**：改为本地 CSV 自缓存——每次拉实时数据后写入，历史越跑越丰富。
- **深股通**：2026-07 实测 sgt 分钟序列常只有几个点、末值量级异常，根因是盘中披露收紧，非代码问题。

## 数据源

### 东财封禁实测（2026-06-30）

- **触发**：选股脚本 10 线程并发、完全不走 `em_get()` 限流，1 小时发出 45000+ 请求（三个版本同时跑全市场 5208 只）。
- **后果**：`push2` / `push2his` 全系列 `RemoteDisconnected`，**IP 级封禁持续 20+ 小时**，不是「几分钟到几小时」的临时限速。
- **观察一**：`datacenter-web.eastmoney.com` 不受影响 —— 东财不同子域走不同 WAF，`push2` 被封不代表整个东财不能用。
- **观察二**：腾讯 K 线（`web.ifzq.gtimg.cn`）连续 5000+ 次后返回空，但这是**限流不是封 IP**，降速或换新浪即恢复。
- **降级耗时**：东财被封时，第一只股票花 10.9s 完成「检测被封 + 降级」，之后每只 0.4s 走腾讯，数据准确。
- **对照**：`em_get()` 默认间隔（1s + 抖动、串行）下 1 小时约 3000 次请求，比踩坑者低一个数量级。
